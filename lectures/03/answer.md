# 第3回 解答

## 演習
- 第1回（素のLLM）とエージェントの回答の違い：素の LLM は講座固有の語を知らず、推測で埋めた（「lecNN」の NN を Neural Network と誤解した）。エージェントは用語集を検索してから答えたので、定義どおり正しく答えた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：`search_glossary` を `'LoRA'` と `'QLoRA'` で1回ずつ、計2回（docstring の「用語を1つだけ入れる」どおり）。
- 1つの質問での LLM 呼び出し回数（`requests`）：2回。2つの検索は1回の応答にまとめて出されたので、ツールを2回呼んでも回数は増えなかった。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)`。その回の用語を1つ選び、問題と答えを返す。docstring には「学習者が理解を確かめる問題を求めたときに使う。answer は学習者が答えるまで見せないこと」と書いた。実行すると `make_quiz(lecture=2)` が呼ばれ、答えを伏せて出題した。

## 宿題

- 取り組んだレベル：発展 (a)（基礎・実装も実施）
- やったこと：発展では、`INSTRUCTIONS` と3つのツールをそのまま ADK の `Agent` に渡し、`adk run` と `adk web` で演習と同じ質問を投げた。基礎では、INSTRUCTIONS と docstring を1か所ずつ変え、各条件で3回ずつ `--trace` を比べた。実装では、`save_learning_log` を `requires_approval=True` で登録し、CLI で y/N を聞くようにして TestModel のテストを書いた（承認待ちの呼び出しには戻り値がないので、既存テストの「呼び出し数 = 戻り値数」も合わせて直した）。
- 結果：
  - 発展：ADK 版も、ツール名・引数・LLM 呼び出し回数は Pydantic AI 版と同じだった。違いはフレームワーク側にあった。`adk run` は会話履歴を引き継ぎ、戻り値を `{'result': ...}` に包み、`.env` を自動で読んだ。`adk web` では、呼ばれたツールだけがグラフで強調された。
  - 基礎：docstring を「用語をまとめて入れる」にすると、検索が2回から1回に減った（3/3）。一方、「必ず検索」の指示を消しても、docstring の使う場面を消しても、「自分の知識で答えてよい」と足しても、検索は止まらなかった（各 6/6 で検索）。
  - 実装：承認すると保存され、拒否すると保存されなかった。ただし、docstring に「保存の前に利用者の確認がある」と書いた版では、モデルがツールを呼ばずに「保存しますか？」と文章で聞き返した（2/2）。
- 気づき・疑問：docstring で「どう呼ぶか」は変えられるが、「呼ぶかどうか」は変えにくかった。また、仕組みが行う確認を docstring に書くと、モデルが自分で確認しようとした。docstring は説明ではなく、モデルへの指示として読まれると感じた。疑問は、ADK で承認付きのツールの「一度止めて再開する」流れをどう書くか。
